For each review, send one request with three questions. For each search query, send one request with a single 40-option `choice` question. I checked this against the live Decisions API docs.

## 1. Reviews: one request per review, three questions

| Need | Type | Why |
|---|---|---|
| Spam? | `noul` | Yes or no. You get back the probability that it is spam. |
| Category | `choice` | Exactly one of 6 categories. You get a probability per category plus a `confidence`. |
| Anger 1–5 | `score` | 5 ordered levels. You get a weighted `score` (it can land between levels, e.g. 3.4) plus the probability of each level. |

```json
{
  "model": "subq-snap-preview",
  "state": {
    "review_title": "Broke after two days",
    "review_text": "The blender lid cracked on day two and support never replied. Waste of money.",
    "star_rating": 1
  },
  "questions": {
    "is_spam": {
      "type": "noul",
      "instructions": "Is this review spam rather than a genuine customer review of a product they used? Judge from review_title and review_text.",
      "criteria": {
        "true": "Advertising, links or promo codes, text unrelated to any product, gibberish, copy-pasted boilerplate, or obvious bot or incentivised text",
        "false": "A real customer describing their own experience with a product, even if short, angry or badly written"
      }
    },
    "category": {
      "type": "choice",
      "instructions": "Which product category is the reviewed product in? Judge from the product described in review_title and review_text.",
      "criteria": {
        "kitchen": "Cookware, small kitchen appliances, utensils, food storage, tableware",
        "audio": "Headphones, earbuds, speakers, soundbars, microphones, audio cables and adapters",
        "outdoor": "Camping, hiking, garden, grills, outdoor furniture, sports and travel gear",
        "toys": "Toys, games, puzzles, children's play equipment",
        "office": "Stationery, desk accessories, office furniture, printers and printing supplies",
        "other": "The product fits none of the categories above, or the product cannot be identified"
      }
    },
    "anger": {
      "type": "score",
      "instructions": "How angry is the customer who wrote review_text? Rate the emotion expressed, not how bad the product is.",
      "criteria": [
        "Not angry: positive or neutral, no complaint",
        "Mildly disappointed: a minor complaint in a calm tone",
        "Clearly annoyed: frustration about a real problem, but measured",
        "Very angry: strong negative language, feels let down or cheated, asks for a refund or warns other buyers",
        "Furious: hostile or abusive tone, accusations of fraud, threats of chargebacks, legal action or public escalation"
      ]
    }
  }
}
```

**Notes:**
- Each level of the anger scale describes a situation that makes sense on its own, ordered from lowest to highest.
- Treat the three answers as independent. The category question doesn't know whether the model thought the review was spam, so your code should check spam first, e.g. `if spam: drop; else: use category and anger`.
- Don't pack several reviews into one request. Keeping one review per state stops one review from influencing the answers about another.

## 2. Search: one request per query, one `choice` with 40 options

Use one `choice` question with the 40 items as its options. Don't send 40 separate yes/no questions: a request takes at most 16 questions, and one choice makes the items compete directly. The limit is 2–255 options, so 40 is fine. Name each option by its catalogue ID and put the title plus description in the option text:

```json
{
  "model": "subq-snap-preview",
  "state": { "search_query": "quiet blender for smoothies" },
  "questions": {
    "best_item": {
      "type": "choice",
      "instructions": "Which catalogue item best matches what the user is looking for in search_query? Pick the single item a shopper would most want to see first.",
      "criteria": {
        "sku_0001": "ProBlend 900 – 900W countertop blender with noise-dampening shield, ideal for smoothies and ice",
        "sku_0002": "TravelMix – USB-rechargeable personal blender, 350 ml bottle",
        "sku_0003": "ChefPro Stand Mixer – 5 L bowl, 10 speeds, dough hook and whisk",
        "...": "... one entry per catalogue item, 40 in total ...",
        "no_match": "None of the catalogue items matches what the user is looking for"
      }
    }
  }
}
```

**Notes:**
- I added a `no_match` option because without it the model must pick an item even for queries like "gift card balance". Remove it if every query is guaranteed to match something.
- The 40 option texts are the same in every request, so build them once in code and reuse them.
- Cost is small. 40 items at about 50–80 tokens each is roughly 2–4K input tokens per query, which works out to about $0.0001–0.0002 per query at $0.05 per 1M tokens. Measure the real figure from `usage.input_tokens`.

## How many requests

- **Reviews:** 1 request per review, carrying all 3 questions. 10,000 reviews means 10,000 requests.
- **Search:** 1 request per query.
- **Total:** reviews + queries. The two tasks have different states, so they can't share a request.

You only need a second request when one answer decides what you ask next. For example, after picking an item you might ask a yes/no question like "does this item actually satisfy the query?" with only that item in the state.

## When to trust the answer

Set the cutoffs from your own labelled data, not from guesses. Label a few hundred reviews and queries, run them through, and choose a cutoff for each question separately. The docs' examples start at 0.6 for a choice's `confidence` and 0.5 for a yes/no probability, but treat those only as starting points.

- **`is_spam`:** use two thresholds with a band in between for people to review. For example: ≥ 0.85 counts as spam, ≤ 0.15 counts as genuine, and anything in between goes to a person. A value near 0.5 means the model is unsure, not "somewhat spam." Set the upper cutoff from what a wrongly deleted real review costs you.
- **`category`:** accept when `confidence` is above your cutoff. Below it, or when the top two `probabilities` are close, send the review to a person or file it as `other`.
- **`anger`:** use the continuous `score` for sorting and alerts, e.g. escalate when `score ≥ 3.8`. If you need a whole number from 1–5, round it, but check `probabilities`. A split such as 45% "mildly disappointed" and 45% "furious" means the review is ambiguous, not that the customer is "annoyed."
- **`best_item`:**
  - Accept when `confidence` is high and the top item clearly beats the runner-up.
  - When `confidence` is low or the top two are close, show the top 3 items by probability instead of one.
  - When `no_match` wins, fall back to keyword search.

**For all four questions:**
- Store the raw probabilities so you can change thresholds later without calling the API again.
- Answers can differ between runs. Measure accuracy on a sample before you automate anything, and re-check now and then, since the model is in public preview and may change.

For the client: read the key from `SUBQ_API_KEY`, retry 429 and 5xx errors with backoff, and don't retry 400 or 422 (fix the request instead). Before sending real review text, check SubQ's data-retention page, since it may contain customer personal data.

## Which question type for each task

| Task | Question type | Why |
|---|---|---|
| Spam | **Yes/no** | It has two outcomes, and you'll want to set the cutoff yourself based on what each kind of mistake costs. |
| Category | **Pick one from a list** (6 options) | The categories don't overlap, and "other" catches anything that doesn't fit. |
| Anger | **1–5 rating** where the order matters | Being off by one should count as less wrong than being off by four. Don't treat the five levels as unrelated labels. |
| Search match | **Pick one from a list**, with a short list first if needed | 40 options is a lot for one question. Accuracy and position bias both tend to get worse with long lists, and SubQ may cap the number of options. |

## How many requests

**Reviews: 1–3 per review.** Ask the spam question first. If the answer is a confident "spam", skip the other two. If SubQ lets you put several questions in one request, it's 1 request per review.

**Search: depends on SubQ's option limit.**
- **Recommended: 1 request.** Use cheap keyword (BM25) or embedding search to narrow the 40 items to the top 8–10. Then ask SubQ to pick one from those, and include a "none of these" option.
- If SubQ accepts all 40 options in one question, that also works in 1 request, but check it for position bias (see below).
- If you can't narrow the list first, run a knockout round: 5 groups of 8, then a final between the 5 winners. That's **6 requests** per query.

## When to trust the answer

Calibrate on roughly 200 reviews and 100 queries that you've labelled by hand, then set a cutoff for each task:

- **Spam:** if SubQ returns a probability, choose the cutoff by what each mistake costs you. For example, auto-drop only above 0.9, and send 0.5–0.9 to a person.
- **Category:** require a gap between the top two options (for example, at least 0.3). Small gaps tend to come from real ambiguity, like a camping speaker that is both "audio" and "outdoor". Send those to a person or allow two labels.
- **Anger:** if SubQ gives a score for each level, use the weighted average, and trust it when most of the weight sits on neighbouring levels. Measure accuracy as within ±1 of your label, not exact matches.
- **Search:** require a clear lead over the second-best item. Also run each question again with the options shuffled: if the winner changes, don't trust it. Treat "none of these" as a real answer, not an error.
- **If SubQ returns no confidence score:** ask each question 3 times (shuffling options where relevant) and trust only answers that agree. That triples the request count.

class SnapError(Exception):

class _NoRedirect(urllib.request.HTTPRedirectHandler):

def _error_detail(e: urllib.error.HTTPError) -> dict:
    try:
        payload = json.load(e)
    except ValueError:
        return {}
    detail = payload.get("detail") if isinstance(payload, dict) else None

def decide(key: str, state, questions: dict, *, attempts: int = 5, timeout_s: float = 60.0) -> dict:
    """One Decisions request with bounded retries on 429/5xx/network errors (exponential backoff, full jitter)."""
    data = json.dumps({"model": MODEL, "state": state, "questions": questions}).encode()
    headers = {"Authorization": f"Bearer {key}", "Content-Type": "application/json"}
    for attempt in range(attempts):
        last = attempt == attempts - 1
        try:
            req = urllib.request.Request(URL, data=data, headers=headers, method="POST")
            with _OPENER.open(req, timeout=timeout_s) as resp:
                return json.load(resp)
        except urllib.error.HTTPError as e:
            detail = _error_detail(e)
            if not (e.code == 429 or e.code >= 500) or last:
                raise SnapError(e.code, detail.get("error_type", "http_error"), detail.get("message", "")) from e
        except (OSError, http.client.HTTPException, ValueError) as e:
            # Timeouts, resets, truncated/invalid bodies: outcome unknown. Retrying is safe (no side effects).
            if last:
                raise SnapError(None, "network", f"{type(e).__name__}: {e}") from e
        time.sleep(random.uniform(0, min(30.0, 1.0 * 2**attempt)))
    raise SnapError(None, "internal", "retry loop ended without a result")


def _argmax_level(probabilities, n_levels: int) -> int | None:
    """Index of the most likely score level; accepts a list or a dict keyed by level text/index."""
    if isinstance(probabilities, list) and len(probabilities) == n_levels:
        return max(range(n_levels), key=lambda i: probabilities[i])
    if isinstance(probabilities, dict):
        criteria = QUESTIONS["severity"]["criteria"]
        scored = {}
        for k, p in probabilities.items():
            if k in criteria:
                scored[criteria.index(k)] = p
            elif str(k).isdigit() and int(k) < n_levels:
                scored[int(k)] = p
        if len(scored) == n_levels:
            return max(scored, key=scored.get)
    return None


def interpret(answers: dict) -> dict:
    """Turn raw answers into a triage decision plus reasons a human should look."""
    reasons = []

    p_urgent = float(answers["urgent"]["noul"])
    if p_urgent >= URGENT_YES:
        urgent = True
    elif p_urgent <= URGENT_NO:
        urgent = False
    else:
        urgent = None
        reasons.append(f"urgency unclear (p={p_urgent:.2f})")

    team_ans = answers["team"]
    team = team_ans["choice"]
    team_conf = float(team_ans["confidence"])
    if team_conf < MIN_TEAM_CONFIDENCE:
        reasons.append(f"team uncertain ({team}, confidence={team_conf:.2f})")
    if team == "other":
        reasons.append("no matching team")

    sev_ans = answers["severity"]
    sev_conf = float(sev_ans["confidence"])
    idx = _argmax_level(sev_ans.get("probabilities"), len(SEVERITY_LEVELS))
    severity = SEVERITY_LEVELS[idx] if idx is not None else None
    if severity is None:
        reasons.append("could not read severity probabilities")
    elif sev_conf < MIN_SEVERITY_CONFIDENCE:
        reasons.append(f"severity uncertain ({severity}, confidence={sev_conf:.2f})")

    # Cheap consistency check: an urgent ticket rated low severity (or vice versa) deserves a look.
    if urgent is True and severity == "low":
        reasons.append("urgent but low severity")
    if urgent is False and severity == "high":
        reasons.append("high severity but not urgent")

    return {
        "urgent": urgent,
        "team": team,
        "severity": severity,
        "needs_human": bool(reasons),
        "reasons": reasons,
    }

class FatalAPIError(Exception):
    """Errors that will affect every request (auth, credits, model access): abort the run."""


class TicketError(Exception):
    """Errors specific to one ticket (bad input, too long, retries exhausted)."""


def load_tickets(path):
    f = sys.stdin if path == "-" else open(path, encoding="utf-8")
    with f:
        raw = f.read()
    stripped = raw.strip()
    if stripped.startswith("["):
        items = json.loads(stripped)
    else:
        items = []
        for line in raw.splitlines():
            if not line.strip():
                continue
            try:
                items.append(json.loads(line))
            except json.JSONDecodeError:
                items.append(line.strip())
    tickets = []
    for i, item in enumerate(items, 1):
        if isinstance(item, dict):
            tickets.append({"id": item.get("id", i), "text": str(item.get("text", ""))})
        else:
            tickets.append({"id": i, "text": str(item)})
    return tickets


def _retry_delay(attempt, retry_after):
    if retry_after:
        try:
            return min(float(retry_after), MAX_BACKOFF_S)
        except ValueError:
            pass
    delay = min(BASE_BACKOFF_S * 2 ** (attempt - 1), MAX_BACKOFF_S)
    return delay * random.uniform(0.5, 1.0)  # jitter


def _error_message(body):
    try:
        detail = json.loads(body).get("detail", {})
        if isinstance(detail, dict):
            return f"{detail.get('error_type', 'error')}: {detail.get('message', '')}"
        return str(detail)
    except (ValueError, AttributeError):
        return body[:500]


def call_snap(api_key, ticket_text):
    payload = json.dumps({
        "model": MODEL,
        "state": {"ticket": ticket_text},
        "questions": QUESTIONS,
    }).encode("utf-8")
    headers = {
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json",
    }

    for attempt in range(1, MAX_ATTEMPTS + 1):
        req = urllib.request.Request(API_URL, data=payload, headers=headers, method="POST")
        try:
            with urllib.request.urlopen(req, timeout=TIMEOUT_S) as resp:
                return json.loads(resp.read().decode("utf-8"))
        except urllib.error.HTTPError as e:
            msg = _error_message(e.read().decode("utf-8", errors="replace"))
            if e.code in (401, 402, 403):
                # Bad key, no credits, or no access to the model: no point continuing.
                raise FatalAPIError(f"HTTP {e.code}: {msg}") from e
            if e.code in (400, 422):
                # Input problem (e.g. ticket too long, invalid request): don't retry.
                raise TicketError(f"HTTP {e.code}: {msg}") from e
            if e.code == 429 or e.code >= 500:
                if attempt == MAX_ATTEMPTS:
                    raise TicketError(f"HTTP {e.code} after {attempt} attempts: {msg}") from e
                delay = _retry_delay(attempt, e.headers.get("Retry-After"))
                print(f"  HTTP {e.code}, retrying in {delay:.1f}s ({attempt}/{MAX_ATTEMPTS})",
                      file=sys.stderr)
                time.sleep(delay)
                continue
            raise TicketError(f"HTTP {e.code}: {msg}") from e
        except (urllib.error.URLError, TimeoutError, ConnectionError) as e:
            if attempt == MAX_ATTEMPTS:
                raise TicketError(f"network error after {attempt} attempts: {e}") from e
            delay = _retry_delay(attempt, None)
            print(f"  network error ({e}), retrying in {delay:.1f}s ({attempt}/{MAX_ATTEMPTS})",
                  file=sys.stderr)
            time.sleep(delay)
        except json.JSONDecodeError as e:
            raise TicketError(f"invalid JSON in response: {e}") from e
    raise TicketError("retries exhausted")  # unreachable


def interpret(answers):
    reasons = []

    urgent_ans = answers.get("urgent") or {}
    team_ans = answers.get("team") or {}
    sev_ans = answers.get("severity") or {}

    p_urgent = urgent_ans.get("noul")
    if p_urgent is None:
        urgent = None
        reasons.append("missing urgency answer")
    else:
        urgent = p_urgent >= 0.5
        lo, hi = URGENT_UNSURE_BAND
        if lo < p_urgent < hi:
            reasons.append(f"urgency ambiguous (p={p_urgent:.2f})")

    team = team_ans.get("choice")
    team_conf = team_ans.get("confidence")
    if team is None:
        reasons.append("missing team answer")
    elif team_conf is not None and team_conf < MIN_CHOICE_CONFIDENCE:
        reasons.append(f"team uncertain (confidence={team_conf:.2f})")

    sev_score = sev_ans.get("score")
    sev_conf = sev_ans.get("confidence")
    severity = None
    if sev_score is None:
        reasons.append("missing severity answer")
    else:
        idx = max(0, min(len(SEVERITY_LEVELS) - 1, round(sev_score)))
        severity = SEVERITY_LEVELS[idx]
        if sev_conf is not None and sev_conf < MIN_SCORE_CONFIDENCE:
            reasons.append(f"severity uncertain (confidence={sev_conf:.2f})")

    # Cross-check: contradictory signals deserve a second look.
    if urgent is True and severity == "low":
        reasons.append("marked urgent but severity low")
    if urgent is False and severity == "high":
        reasons.append("high severity but not marked urgent")

    return {
        "urgent": urgent,
        "urgent_probability": p_urgent,
        "team": team,
        "team_confidence": team_conf,
        "team_probabilities": team_ans.get("probabilities"),
        "severity": severity,
        "severity_score": sev_score,
        "severity_confidence": sev_conf,
        "needs_human": bool(reasons),
        "review_reasons": reasons,
    }
